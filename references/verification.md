# 验证及交付证据

本技能不是“安装命令跑完就结束”。在接收者机器上记录每一层的实际结果，失败时留下原始错误与未完成事项。

## 最小可交付范围

1. 真实下载并安装运行时及插件，原生配置验证成功。
2. ChatGPT 登录后台保存成功；真正使用选定模型回复一次。页面同意、账号已登录或公开端点 200 都不能替代模型请求。
3. 本地同会话第二轮记住随机暗号。空工具报告、Codex harness、实际模型匹配；一次指定文件创建尝试未落盘。Test-Model.ps1 会生成模型测试摘要。若当前版本不提供该结构，检查该版本原生报告，不把“字段缺失”当成空工具。
4. 用户扫码确认，微信通道开始运行。
5. 用户从手机发文字，插件有 inbound，真实模型会话有回复，插件记录发送成功，用户确认手机看到。
6. 同一微信聊天再追问上一条，内容正确；比对手机确认及对应日志。

不要自己向别人的微信好友、群聊或联系人发测试消息。让当前用户在绑定的个人 ClawBot 里发起并确认回复。

## 证据记录建议

在项目的 SETUP-STATUS.md 维护一个简短表格：阶段、状态、时间、证据文件、剩余问题。原始记录留在运行项目，分享包只放明确脱敏的测试结论。

原生 agent --json 的本基线报告中，result.meta.agentMeta 包含 model、provider、agentHarnessId；result.meta.systemPromptReport.tools 包含 entries、schemaChars；result.payloads 是回复。只有真实请求成功后才能记录模型通过。

通道日志通常在项目 .tmp/openclaw，网关日志在 logs。关联同一 account/peer 和时间，不因刚好有其他消息就推断本次成功。此版本 lastOutboundAt 可能未更新，实际 outbound: text sent OK 与用户确认更直接。若用户文字与建议的测试句不同，以实际文字判断回忆是否正确。

## 不把测试范围扩大

- 解析器或 skill frontmatter 校验：只说明格式可解析。
- 空目录生成测试：只说明生成逻辑、拒绝覆盖等对应分支。
- 离线构造消息、假服务器或函数测试：只说明局部机制；不代表真实安装或账号登录。
- 原生安装及启动：不代表模型已授权，更不代表手机收到消息。
- 两轮微信文字收发：是该账号、该设备、该时段的真实端到端验证，不覆盖长时间在线、断网恢复、重启、群聊、语音、图片和所有安全路径。

结束时用普通语言报告：当前可用的功能、当前是否运行、如何启动/停止、账号额度和电脑网络要求、真正测过什么、没测什么。不要写“全部测试通过”“完全验证”“保证可用”。
