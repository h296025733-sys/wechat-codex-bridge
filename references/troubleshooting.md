# 按失败层排错

先记原生命令、退出码、时间和对应日志。可公开摘要应隐去凭据、邮箱、微信账户 ID、context token 和聊天正文。不要为了排错输出整份配置、auth.json 或数据库。

| 现象 | 先确认什么 | 合理下一步 |
| --- | --- | --- |
| npm EALLOWSCRIPTS | 是否在没有 package.json 的目录使用了 --allow-scripts | 本脚本用独立 --global --prefix；不能把失败叫安装完成。不要根据 npm 提示修改全局用户策略 |
| 安装脚本警告某些可选依赖未允许运行 | 是否影响当前文字聊天、插件加载或原生错误 | 先验证实际所需能力，不一口气放开全部脚本 |
| 已有其他 OpenClaw | 目录、端口、进程归属 | 使用独立目录/端口，不能按进程名杀掉所有 node.exe |
| 配置字段 unknown / invalid | 实装版本的 config schema 和 --help | 调整具体字段并 dry-run，保留聊天权限；不要降级成全权限配置 |
| 页面已同意但后台登录失败 | OAuth 进程最后的 token exchange 错误及是否保存 profile | 解决具体错误后再发起一次新登录；不能使用用户的“已完成”替代后台证据 |
| 没有弹出浏览器、工具显示 queued | 当前授权/配对进程是否仍在等待、URL 是否有效 | 通过可用浏览器打开或给有效链接；二维码直接显示本地 PNG。开页返回 0 不等于用户看见 |
| 设备码或 token exchange 返回 403 | 完整错误码：地区、账号、组织策略、风控还是其他 | 公开 discovery 的 200 不能证明 token endpoint 允许。若明确为地区/账号限制，说明限制并停止机械重试；不能靠反复授权解决 |
| Node 请求失败、浏览器正常 | Node 是否继承当前用户已有代理、代理进程是否运行、证书/超时错误 | 运行项目 Detect-Network、Probe-Network；仅沿用已有且适用的网络设置，不编造代理，不把所有 403 归因网络 |
| localhost readiness 检查失败 | Windows 系统代理是否连本地请求也接管 | 使用 helper 的 HttpClientHandler.UseProxy=false；不能只看到进程就报告服务 ready |
| 端口占用 | 端口监听者归属 | 另选端口并同步本项目配置；别停别人的服务 |
| 网关 ready，但模型不回复 | 本项目 auth profile、可用模型、额度及真实请求错误 | 分别核对登录、模型权限和原生请求；ready 只证明本机服务 |
| 新目录没有手动登录却能调用 | Check-Auth 的 OAuth 方式和本机已有 Codex 身份 | 该版本支持本地 OAuth bootstrap。核对属于当前用户后可沿用；不要伪称执行过新登录，也不要清空用户凭据来制造无授权测试 |
| Codex 版本太旧或插件 API 不匹配 | 插件实际调用的 Codex 二进制，不只系统 CLI 版本 | 使用插件管理的匹配运行时；不要为图省事改成 user homeScope 导入整个桌面状态 |
| 用户只看见 ChatGPT 授权、没有微信二维码 | 当前执行的是哪个阶段 | 授权结束后另运行 Pair-WeChat；不要重复 ChatGPT 授权 |
| 微信二维码过期 | 活跃 CLI 是否已刷新、新 PNG 修改时间、网页缓存 | 当前配对页会刷新；若登录已结束，重新启动配对并展示新码。不能反复发送旧截图 |
| 扫码成功但通道还没启动 | CLI 原生结果、channels status 和通道启动日志 | 先等热更新；必要时只重启本项目。无需先解绑重扫 |
| lifecycle=starting / lastOutboundAt=null | 插件自己的 monitor、inbound、outbound 日志 | 此基线可能未更新通用状态字段。用实际消息记录和手机确认判断，不能单凭空字段否定已发送 |
| 微信里收到消息但没回答 | 是否到达模型、是否生成、微信 send 是否出错 | 沿同一消息逐层跟踪；不要通过“再发十条”制造重复 |
| 首轮正常、第二轮忘记 | 是否同一 account/channel/peer 会话键、是否换了聊天或重建会话 | 保留 per-account-channel-peer；检查真实两条内容及会话路由，别假装有跨客户端记忆 |
| 模型自称能读写电脑 | 实际工具清单、Codex 原生受限模式、探针文件 | 自称不等于动作。若确有工具或文件被创建，先停测试并修权限，不报告聊天隔离成功 |
| 电脑重启后不回复 | 本项目是否启动、代理是否运行 | 启动服务并检测，不重新授权；默认未装开机自启 |

## 受控重试

对同一失败，只有出现了具体变化（修正代理继承、清理已结束的回调监听、换成账户已支持的登录方式、更新已核对的配置）才重试。一次有理由的重试仍同样失败就先调查证据或请用户解决外部条件，不消耗其授权操作次数。保留成功阶段，重跑失败阶段；不删除凭据来“碰碰运气”。

## 诊断与恢复命令

项目 OpenClaw.ps1 为每个子进程加载独立环境。使用它执行 config validate、plugins list --json、models status --json、channels status --json、对应命令 --help。输出先存本机，再只提取所需字段；models status 可能含账号标识，不整份公开。

状态在 state、logs 和 .tmp/openclaw。修配置前保留本机备份，但备份同样可能含凭据。没有明确清理要求，不递归删除目录。停止脚本以项目 ID、进程开始时间、路径核对 PID，拒绝终止身份不符的进程。

微信截图中的 24 小时规则是发送消息后的回复窗口，不能解释为整个机器人只能使用一天；当前账号具体规则应以微信页面为准。
